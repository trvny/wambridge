# WAM event listener

`wambridge-events` keeps one TCP connection open to the speaker on port `55001` and sends a harmless `GetFunc` request through a separate writer connection. This matches the connection model used by pywam and exposes responses plus unsolicited events generated by other clients.

## Usage

Resolve a saved device and listen until Ctrl+C:

```powershell
wambridge-events --device M5
```

Print complete XML bodies:

```powershell
wambridge-events --device M5 --raw
```

Stop automatically after two minutes:

```powershell
wambridge-events --device M5 --duration 120
```

Use a known client identity when comparing sessions:

```powershell
wambridge-events --device M5 `
  --client-uuid b00524c5-87b8-4439-9bb6-010545a40948
```

Without `--client-uuid`, the command generates a temporary UUID and prints it at startup.

## Useful events

- `DMSAddedEvent`: DMS registration accepted.
- `MediaBufferStartEvent`: buffering started.
- `MediaBufferEndEvent`: buffering completed.
- `MusicInfo`: current object and playback capabilities.
- `StartPlaybackEvent`: actual playback start.
- `MusicPlayTime`: current and total playback time.
- `ErrorEvent`: firmware error; use `--raw` to retain all fields.

The listener observes speaker responses and events. It does not capture the exact outgoing HTTP request made by another client.
